# running.services

- Production origin: https://running.services (see `wrangler.jsonc`). Deploy through the existing Cloudflare Worker, using `npm run build` and `wrangler deploy`.
- Public products: race discovery and comparisons, race listings for organizers, and an authenticated read-only race API. Verify current claims on /for-organizers, /pricing, /developers, or in their source before publishing.
- The 2027 guide hub supports all 50 states. Guides read the current race catalog, exclude expired races during their season, and qualify automatically for the guide sitemap as sourced coverage improves. Run `node script/verify-race-guides.mjs https://running.services` to check server rendering and sitemap parity. In the weekly pass of the existing scheduled SEO job, run that check and record which state guides need more sourced races. Recheck the featured New York and Florida organizer links and the wording of time-sensitive advice. When the catalog is stale, use the existing RunSignup ingestion and Cloudflare access to refresh verified listings before changing the guide. Preserve claimed races and existing URLs. Treat unverified prices and dates as unavailable.
- Blog pages are generated by `shared/blog-months.ts`, `client/src/pages/blog-post.tsx`, and `server/ssr-prefetch.ts`. Prefer slug-specific content where only one URL qualifies.
- Race comparisons use the existing /vs route. Check both race records and the canonical pair before creating or linking a comparison.
- Acquisition focus: race organizers and developers. GA4 `generate_lead` records accepted API requests, race claim requests, race-guide alert subscriptions and other lead types. `race_claim_verified` measures completed claims separately.
